# VPf08 — product-mcp: спецодежда и СИЗ

Учебный MCP-проект: SQLite-каталог и Telegram-агент. Модель получает схемы
инструментов от MCP-сервера, выбирает инструмент, приложение вызывает его по
HTTP и передаёт результат модели для ответа пользователю.
Все товары, размеры и цены демонстрационные. Проект не связан с реальным складом,
1С или сайтом продавца и не подтверждает защитные свойства изделий.

## Возможности

| Инструмент | Назначение |
| --- | --- |
| `list_products` | Список товаров, ID, категория, цена RUB, пагинация |
| `find_product` | Поиск по части названия, включая кириллицу без учёта регистра |
| `add_product` | Добавление названия, категории и положительной цены |
| `calculate` | AST-калькулятор без `eval`, вызовов функций и доступа к объектам |
| `list_categories` | Категории и количество товаров |
| `find_products_by_category` | Категория + диапазон цены включительно |
| `quote_order` | Стоимость заявки по ID, количеству и скидке 0–30% |

Первые четыре инструмента реализуют базовый пример урока. Последние три — расширение
под торговлю спецодеждой и СИЗ. При первом запуске создаются 100 товаров в 10 категориях.
Повторный запуск сохраняет изменения и не добавляет тестовые товары повторно.
Деньги в заявке рассчитываются через `Decimal`, округление скидки — до копеек.
Заявка не оформляется, товары не резервируются; доставка и налоги отдельно не рассчитываются.
Одинаковое название и категория с той же ценой не создают дубликат.

## Структура

```text
mcp_server/
  server.py          # MCPServer, JSON Schema и регистрация инструментов
  db.py              # SQLite, инициализация 100 товаров, расчёт заявки
  tools.py           # ограниченный AST-калькулятор
  requirements.txt
telegram_bot/
  bot.py             # aiogram, личные чаты, команды, разбиение длинных ответов
  config.py          # .env, доступ, журналирование и блокировка процесса
  mcp_client.py      # официальный MCP SDK: initialize → tools/list → tools/call
  agent.py           # цикл выбора и вызова инструментов через OpenAI
  prompt.py          # системный промпт предметной области
  requirements.txt
tests/
check_mcp.py         # реальный HTTP и временная SQLite без API-ключей
check_live.py        # платные OpenAI-запросы и HTTP MCP во временной базе
run.py               # один запрос через CLI
requirements.txt
requirements-lock.txt
.env.example
```

## Установка

Проверено: Python 3.13.13, macOS, MCP SDK 2.3.0. Используется встроенный SQLite;
пакет `sqlite3` устанавливать через pip не требуется. MCP SDK сам включает
Starlette и uvicorn для HTTP-сервера.

Из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
cp .env.example .env
```

В `.env` заполните `OPENAI_API_KEY` и `BOT_TOKEN`. Сохраните токен только локально.
По умолчанию модель `gpt-6-luna`, как в VPf07; можно задать `CHAT_MODEL` и
`OPENAI_BASE_URL`. Для доступа к OpenAI нужны рабочий ключ, доступ к модели и баланс.

В `.env` можно указать `ALLOWED_USER_IDS` — Telegram ID через запятую.
Если список пуст, бот отвечает во всех личных чатах. Группы игнорируются.
В учебном проекте разрешённые пользователи имеют общий каталог и право добавления.

## Запуск

Терминал 1:

```bash
.venv/bin/python -m mcp_server.server
```

Сервер слушает `http://127.0.0.1:8008/mcp` через **Streamable HTTP**.
Это официальный MCP: инициализация, согласование версии, `tools/list`, `tools/call`,
JSON Schema и типизированные результаты реализует MCP SDK. Обычных REST-ручек вместо
MCP нет. Сервер локальный, без сетевой авторизации; адрес привязки loopback.
Для другого порта согласованно поменяйте `MCP_PORT` и `MCP_URL`.
База автоматически появится в `data/products.db`. Путь можно задать `PRODUCTS_DB`;
относительный путь отсчитывается от корня проекта.

Терминал 2:

```bash
.venv/bin/python -m telegram_bot.bot
```

Можно запускать и как в уроке: `.venv/bin/python mcp_server/server.py` и
`.venv/bin/python telegram_bot/bot.py`. Остановка — Ctrl+C в обоих терминалах.
Не запускайте одновременно VPf07 и VPf08 с одним `BOT_TOKEN`: Telegram допускает
одного polling-получателя. Исходный проект VPf07 остаётся отдельным.
Webhook автоматически не удаляется: при его наличии бот объяснит причину отказа запуска.

В качестве альтернативы Telegram, при работающем MCP-сервере:

```bash
.venv/bin/python run.py --ask 'Найди перчатки'
```

## Диалог

```text
/start
Покажи все товары
Найди каски
Какие категории есть в каталоге?
Покажи товары категории Защита рук от 100 до 150 рублей
Добавь товар Перчатки Нитрил Тест, категория Защита рук, цена 125.50 рублей
Найди этот добавленный товар
Рассчитай 10 штук товара ID 41 и 2 штуки ID 51 со скидкой 5%
Сколько будет (2400 * 5 + 90 * 20) * 0.95?
Добавь товар каска
/reset
```

Последний запрос без категории и цены должен вызвать уточнение.
`/help` показывает справку. `/reset` удаляет контекст своего пользователя, сохраняя каталог.
Последние 8 пар вопрос–ответ хранятся отдельно для каждого пользователя в памяти процесса.
После перезапуска контекст очищается; SQLite сохраняется.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python check_mcp.py
# Реальные платные обращения к OpenAI, Telegram getMe/getWebhookInfo:
.venv/bin/python check_live.py
```

`check_mcp.py` создаёт временную БД и HTTP-сервер на свободном порту, выполняет
14 проверок: все 7 инструментов и их схемы, каталог, поиск, фильтр, запись,
калькулятор, заявка, отклонение ошибочных аргументов и опасных выражений.
`check_live.py` использует те же классы агента и MCP-клиента, что Telegram-бот,
но не отправляет Telegram-сообщения. Протокол сохраняется локально в
`local_checks/live_check.json`. Саму переписку в Telegram проверяют отдельно.

## Ограничения и данные

Используется OpenAI **Responses API** и нативный function calling с моделью VPf07.
В уроке Chat Completions приведён в примере генерации; архитектура MCP-сервера,
клиента и Telegram-агента сохранена. Схемы берутся через `tools/list`, вручную
дублировать их в промпте не требуется. Лимит — 8 шагов модели на сообщение.
Текст запроса и результаты выбранных инструментов передаются в OpenAI;
`store=False` отключает сохранение Response для получения через API.
Журнал приложения содержит названия инструментов и типы ошибок без токенов.

`.env`, `.venv`, SQLite, журналы и локальные протоколы исключены из репозитория
через `.gitignore`. В репозитории есть `.env.example` с пустыми ключами. Реальные
секреты пользователь указывает в локальном `.env` после клонирования. Для промышленного применения потребуются
учёт остатков, реальные характеристики и документы на СИЗ, роли и резервирование.
